# MOSS-Image-Cai 桌面版 · 本地使用说明

> 应用已改名 **MOSS-Image-Cai**，并做成“**双击即启动服务 + 打开窗口**”的一体化 App。
> 开机登录后服务也会由 LaunchAgent 自动拉起，App 随开随用。

---

| 项目 | 变化 |

## 3. 安装（只需一次）

1. 双击 `MOSS-Image-Cai_0.1.1_aarch64.dmg`，把 **MOSS-Image-Cai.app** 拖进「应用程序」。
2. 首次打开可能被 Gatekeeper 拦截：
   - 右键 App → 打开 → 再点“打开”；
   - 或执行一次：`xattr -dr com.apple.quarantine /Applications/MOSS-Image-Cai.app`
3. 若旧版 `MOSS-Image.app` 还在，先退出并删除，避免两个图标混淆。

---

## 4. 日常使用：双击即可

打开 `/Applications/MOSS-Image-Cai.app` 后，壳会：

1. 检查 `127.0.0.1:7860` 是否在线；
2. 不在线则 `launchctl bootstrap/kickstart` 启动 LaunchAgent，并最多等 90 秒；
3. 服务就绪后打开内层窗口（猫图标）。

实测冷启动：服务从 0 到就绪约 **12 秒**；日志在 `~/MOSS-Image/logs/launcher.log`。

**手动等价方式**（调试用）：

```bash
~/MOSS-Image/launcher.sh          # 确保服务在线
open -a /Applications/MOSS-Image-Cai.app
```

停止服务：`launchctl bootout gui/$(id -u)/com.moss.image.workbench`

## 5. 开机自启服务（LaunchAgent）

- 配置文件：`~/Library/LaunchAgents/com.moss.image.workbench.plist`
- Label：`com.moss.image.workbench`
- 行为：登录即启动（`RunAtLoad`），崩溃自动拉起（`KeepAlive`），10 秒节流
- 启动命令：`cd ~/MOSS-Image && exec ./.moss/ui/start.sh`
- 日志：`~/MOSS-Image/logs/launchagent.out.log` / `.err.log`

常用命令：

```bash
launchctl print gui/$(id -u)/com.moss.image.workbench   # 查看状态
launchctl kickstart -k gui/$(id -u)/com.moss.image.workbench  # 重启服务
launchctl bootout gui/$(id -u)/com.moss.image.workbench       # 停止并卸载
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.moss.image.workbench.plist  # 重新加载
```

> 注意：服务必须在**非受保护目录**（`~/MOSS-Image`）运行，否则 launchd 无权读取桌面里的脚本。

## 6. 界面使用说明

| 区域 | 说明 |
| --- | --- |
| 提示词 | 支持中英混排、`\n` 换行；可直接写要渲染进画面的文字 |
| 反向提示词 | 默认已含质量/乱码抑制词，一般不用改 |
| 画布尺寸 | 16:9 1280×720（PPT 横版）、1:1 1024、4:3、3:4 |
| 随机种子 | 42 可复现；-1 每次随机 |
| 步数 / CFG | 默认 50 步 + CFG 3；勾 turbo 时步数被忽略 |
| turbo | 15 次网络前向，速度快数倍 |
| 常驻显存 | 更快但内存约 11 GB（16 GB 机器慎用） |
| Layout JSON | 精确排版 JSON，自动校验越界 |
| 输出 | 落在 `~/MOSS-Image/moss-ui/out/`（旧路径 `ppt-sum/moss-ui/out` 为历史产物） |

耗时参考（M4 / 16 GB）：1280×720 turbo 约 5–6 分钟；官方 50 步约 12–15 分钟。

## 7. 常见问题

| 现象 | 处理 |
| --- | --- |
| 双击 App 白屏/转圈 | 看 `~/MOSS-Image/logs/launcher.log` 与 `launchagent.err.log`；再手动跑 `~/MOSS-Image/launcher.sh` |
| 端口 7860 被占 | `lsof -nP -iTCP:7860 -sTCP:LISTEN` 找到进程后 `kill <PID>` |
| 服务反复重启 | `launchctl print` 看 last exit code；多半是端口冲突或模型路径缺失 |
| 生成慢/卡 | 关掉占内存应用；确认勾 turbo；swap 满时速度会掉一半以上 |
| 首次打开被拦 | 右键 → 打开；或 `xattr -dr com.apple.quarantine /Applications/MOSS-Image-Cai.app` |
| 模型缺失 | 确认 `~/MOSS-Image/.moss/models/MOSS-Image-SFT-MLX-compact`（12.08 GB） |

## 8. 数据与隐私

- 推理全在本机；除首次从 HuggingFace 镜像下载权重外，不上传提示词或图片。
- 输出与缓存都在 `~/MOSS-Image/`；服务仅监听 `127.0.0.1`。
- LaunchAgent 只启动本地 Python 服务，不对外联网（除模型下载/镜像）。

## 9. 卸载

```bash
launchctl bootout gui/$(id -u)/com.moss.image.workbench
rm -f ~/Library/LaunchAgents/com.moss.image.workbench.plist
rm -rf /Applications/MOSS-Image-Cai.app
# 谨慎：同时会删除 13 GB 模型与工作台
# rm -rf ~/MOSS-Image
```

桌面软链 `~/Desktop/ppt-sum/.moss` 仍指向 `~/MOSS-Image/.moss`，删环境后需一并清理。

## 10. 技术信息

- 外壳：AppleScript App（`com.moss.image.launcher`），内嵌 Pake/Tauri Web App（`com.moss.image`），URL 固定 `http://127.0.0.1:7860`
- 服务：`~/MOSS-Image/.moss/ui/app.py`（Gradio 6），由 LaunchAgent 托管
- Pake 版本：3.18.0，Tauri 2，target `aarch64-apple-darwin`
- 构建：`moss-app/` 下 `npx pake ... --app-version 0.1.1 --targets dmg`；DMG 步骤被沙箱拦截时用 `hdiutil` 手动打包
- 图标：狸花猫 B 版（`moss-cat/cat-b.icns`）
